# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ARCHITECTURAL SPECIFICATION)
## Проект: Кастомный SPL-токен на Solana (Anchor Framework)

### 1. Архитектура и Стек
- Язык: Rust
- Фреймворк: Anchor (версия 0.30.0+)
- Стандарт: SPL Token / Token 2022 (в зависимости от выбора логики)

### 2. Функциональные требования к смарт-контракту (Program)
- Инициализация (Initialize): Создание Mint-аккаунта токена. Управление правами (Mint Authority, Freeze Authority) передается Program ID или контролируемому PDA (Program Derived Address).
- Кастомный Mint: Функция чеканки токенов, защищенная проверкой прав (has_one = authority или проверка подписи PDA).
- Кастомный Burn / Transfer Hook (Опционально): Реализация логики сжигания процента токенов при транзакции или комиссионных сборов (если выбран Token 2022).

### 3. Требования к Безопасности (Security Constraints)
- Строгая проверка аккаунтов через макросы Anchor #[derive(Accounts)].
- Использование типов Signer<'info> для всех административных подписей.
- Защита от атак повторного входа (Reentrancy) и Integer Overflow (использовать безопасную математику Rust или встроенные проверки Anchor).
- Валидация ассоциированных токен-аккаунтов (Associated Token Accounts) через AssociatedToken программу.

### 4. Инфраструктура для Клиента (TypeScript/JavaScript SDK)
- Скрипт деплоя и инициализации через @solana/web3.js и @coral-xyz/anchor.
- Генерация ключевых пар (Keypairs) локально для тестов.
- Логика подписи транзакций на клиенте и отправка в Testnet/Devnet RPC.
